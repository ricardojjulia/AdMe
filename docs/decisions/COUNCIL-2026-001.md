# COUNCIL-2026-001: Initialize Code Factory System

**Status:** RATIFIED — Completed
**Date:** 2026-06-16
**Council:** Architecture Council, AdMe (6/6 unanimous)
**Related:** None
**Tags:** governance, ci-cd, versioning, testing

## Context
The AdMe platform requires an automated, robust governance system to enforce codebase quality, security by construction, and version consistency constraints. Prior to this decision, version matching was manual, unit test coverage lacked standard reporting thresholds, and reviews for critical path modifications were not codified.

## Decision
We will initialize the Code Factory System in the repository. This commits the codebase to version consistency checks, automated CI pipeline validation, codeowner approvals, and strict testing standards.

## Amendments Adopted
1. Preserve the existing Playwright E2E browser tests under `/tests/e2e/adme.spec.ts` to protect existing UI validation coverage.
2. Use per-file coverage thresholds for partially-tested domains (e.g. `src/lib/i18n/adapter.ts` at 65% and `src/lib/i18n/client.ts` at 55%) instead of directory-wide thresholds, preventing untested modules from blocking CI.
3. Configure the Vitest environment to `node` for unit and integration testing to eliminate dependency on missing browser packages like `jsdom`.

## Implementation Mandate
- Script: `scripts/check-version.mjs` comparing `package.json` with the leading line of `CHANGELOG.md`.
- Workflow files: `.github/workflows/ci.yml` (Lint, Typecheck, Test, Build) and `.github/workflows/release.yml` (Staging -> Manual Approval -> Production migrations deploy).
- Mocks: `src/tests/setup.ts` mocking `next/navigation`, `next/cache`, and `@/lib/supabase/*` clients.
- Code Ownership: `.github/CODEOWNERS` restricting approvals for workflows, migrations, and supabase clients to `@ricardojjulia`.
