# COUNCIL-2026-012: Sensory Shield & Cognitive Comfort Mode for Neurodivergent-Friendly, Low-Stimulus Ad Viewing

**Status:** RATIFIED — COMPLETED
**Date:** 2026-09-28
**Council:** Architecture Council, AdMe (6/6 ratified)
**Related:** COUNCIL-2026-001
**Tags:** council, automatic, live-governance, privacy, location

## Context
Modern digital advertising often relies on aggressive micro-animations, flashing badges, pulsing attention-grabbers, and high-motion canvas interactions to combat banner blindness. For neurodivergent users (such as individuals with ADHD, autism, or vestibular sensitivities) and general consumers seeking mindful, low-stimulus environments, these high-motion patterns cause sensory overload, cognitive fatigue, and acute annoyance. Consumers demand respectful, non-intrusive ad delivery where visual stimulus can be curbed without losing access to valuable merchant discounts or rewards.

## Decision
Implement an end-to-end Sensory Shield & Cognitive Comfort Mode across AdMe: 1. Client-Side Sensory Comfort Engine & Preferences: Integrated into user settings and local state, providing a persistent Sensory Shield toggle that activates low-stimulus, reduced-motion rendering. 2. CSS Architecture & Root Attribute Modulation (data-sensory-mode='comfort'): Global design tokens that automatically disable CSS keyframe animations, subdue pulsating indicators, reduce saturated color contrast, and enforce high-legibility typography. 3. Sensory-Adaptive Component Rendering: Adapt rich canvas components (InteractionUnits, GeofenceAlert, FeedCard) so that scratch-off games and dynamic animations seamlessly transform into calm, accessible, single-click reveal cards. 4. Floating Sensory HUD / Quick Toggle: A non-intrusive, glassmorphic floating control allowing users to instantly switch between dynamic and calm modes directly from the feed. 5. Localization: Full bilingual translation support in English and Spanish (en.json, es.json). 6. Privacy & Testability: 100% client-side ephemerality with zero tracking, validated via Vitest unit tests and Playwright E2E browser journeys.

## Amendments Adopted
1. All sensory preference state must be stored locally using a namespaced localStorage key (e.g., 'adme_sensory_shield_v1') and initialized safely to respect system-level 'prefers-reduced-motion' media queries by default.
2. Bilingual localization keys for English and Spanish must be added atomically to both en.json and es.json simultaneously to prevent locale mismatch bugs in the floating HUD.
3. Playwright E2E tests must include explicit assertions confirming that CSS animations and keyframes are entirely disabled on target DOM nodes when data-sensory-mode='comfort' is active.

## Implementation Mandate
Proceed with development adhering to the following structure: 1. Update root layout/html attributes to react to data-sensory-mode='comfort'. 2. Build the glassmorphic Floating Sensory HUD component with English and Spanish localization in en.json and es.json. 3. Refactor InteractionUnits, GeofenceAlert, and FeedCard to gracefully fall back to single-click reveal states. 4. Implement Vitest unit tests for state management and Playwright specs for E2E validation.

## Council Deliberations
### 🏛️ The Architect (YES)
The implementation of data-sensory-mode='comfort' at the root DOM level via CSS variable token overrides is a textbook enterprise pattern. It avoids React tree re-renders for styling shifts, ensuring buttery-smooth transitions and zero layout thrashing when toggling the Sensory Shield HUD.

### ⚙️ The Engineer (YES)
Component transformation from canvas scratch-offs and high-motion feed cards to single-click reveal states is clean and robust. TypeScript interfaces must cleanly enforce a unified SensoryAdaptiveProps contract across InteractionUnits, GeofenceAlert, and FeedCard to prevent brittle prop drilling.

### 🛡️ The Security Lead (YES)
100% client-side ephemerality using localStorage/React state guarantees that a user's neurodivergent preferences or sensory sensitivities are never transmitted to our backend or analytics pipelines, fully satisfying our zero-knowledge telemetry constraints.

### 🎯 The Product Owner (YES)
This directly champions user agency and inclusion. By preserving full access to merchant rewards and discounts while stripping away cognitive fatigue and aggressive animations, we build deep trust with neurodivergent consumers and mindful shoppers alike.

### 🧪 The QA Lead (YES)
Test coverage strategy is bulletproof. Vitest will validate state preservation and local preference persistence, while Playwright E2E journeys will explicitly test the glassmorphic floating HUD toggle and verify CSS variable mutations across viewports.

### 💾 The Data Engineer (YES)
Zero database schema changes are required since preferences remain purely client-side. This completely eliminates retention policy risks and database migration overhead while achieving zero-tracking compliance by design.
