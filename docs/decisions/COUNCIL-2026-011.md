# COUNCIL-2026-011: Ephemeral Contextual Intent Tuner and Client-Side Zero-Tracking Feed Personalization Engine

**Status:** RATIFIED — Completed
**Date:** 2026-09-22
**Council:** Architecture Council, AdMe (6/6 ratified)
**Related:** COUNCIL-2026-001
**Tags:** council, automatic, live-governance, privacy, location

## Context
Conventional ad networks rely on invasive surveillance and persistent behavioral profiling to infer user intent, creating severe privacy violations and algorithmic pigeonholing. User research reveals that ad reception is highly situational: a user may want local dining deals on Friday evening, low-stimulus reading on Sunday morning, or strictly independent artisan discovery while traveling. Users require dynamic, instant agency over their current commercial feed context without saving persistent tracking cookies, submitting PII, or compromising application responsiveness.

## Decision
Implement an end-to-end Ephemeral Contextual Intent Tuner & Client-Side Personalization Engine: 1. Floating Intent Tuner Filter HUD: A lightweight, accessible glassmorphic pill selector mounted atop the consumer feed supporting 4 distinct situational intent modes ('All-Around Discovery', 'Local Gems', 'Deal Hunter', 'Mindful / Low-Stimulus'). 2. Pure Client-Side Deterministic Re-ranking: A pure TypeScript ranking utility ('intent-tuner.ts') that evaluates ad metadata (merchant type, discount availability, ethical score, content density) against active intent without server-side tracking or profile storage. 3. Intent Resonance Micro-Badges: Render visual intent matching indicators on feed cards confirming why each card resonates with the user's selected mode. 4. Zero-Tracking Local Ephemerality: Intent state is kept strictly in React state / ephemeral session memory, ensuring zero central logging of user situational moods while supporting i18n localization in English and Spanish.

## Amendments Adopted
1. Ensure 'intent-tuner.ts' runs inside a lightweight Web Worker or is memoized via useMemo to prevent main thread blocking during heavy feed re-renders.
2. Verify that i18n translation keys for the 4 situational intent modes ('All-Around Discovery', 'Local Gems', 'Deal Hunter', 'Mindful / Low-Stimulus') are fully populated in both en.json and es.json locale dictionaries.

## Implementation Mandate
Implement the feature with the following file structure and technical patterns: 1. Create client-side utility in 'src/utils/intent-tuner.ts' containing the deterministic re-ranking logic for merchant type, discount availability, ethical score, and content density. 2. Build the floating glassmorphic HUD component in 'src/components/feed/IntentTunerHUD.tsx' using React state for volatile session memory. 3. Add Intent Resonance Micro-Badges to feed cards in 'src/components/feed/IntentResonanceBadge.tsx'. 4. Ensure complete localization support within 'src/locales/en.json' and 'src/locales/es.json'.

## Council Deliberations
### 🏛️ The Architect (YES)
The Next.js architecture remains completely clean by executing the re-ranking algorithm via a pure TypeScript utility on the client side, avoiding any server-side roundtrips or API log pollution. The floating glassmorphic HUD fits neatly inside our component hierarchy without layout thrashing.

### ⚙️ The Engineer (YES)
The 'intent-tuner.ts' implementation is extremely performant and easy to maintain with strict TypeScript types for the 4 intent modes. Using React state for ephemerality guarantees zero DOM-storage footprint and seamless i18n key lookups for English and Spanish.

### 🛡️ The Security Lead (YES)
This design strictly enforces our zero-tracking mandate. By keeping situational moods exclusively in volatile client memory and avoiding persistent cookies or PII transmission, we eliminate user profiling and entirely mitigate server-side surveillance vectors.

### 🎯 The Product Owner (YES)
This delivers immediate user agency over commercial feeds, solving algorithmic pigeonholing. The 4 intent modes directly address contextual variance like weekend dining vs. calm Sunday reading, vastly boosting user trust and engagement satisfaction.

### 🧪 The QA Lead (YES)
The testing strategy is straightforward. We can unit test 'intent-tuner.ts' with isolated mock metadata objects across all 4 modes, and verify React state ephemerality and micro-badge rendering using React Testing Library and i18n mock providers.

### 💾 The Data Engineer (YES)
Zero database schema changes are required, which perfectly aligns with our zero-retention compliance policies. The database remains completely decoupled from user intent states, ensuring absolute data minimization.
