# COUNCIL-2026-009: Instant Value-Exchange Voucher Minting ('Claim to Wallet') and Client-Side Anti-Fatigue Attention Shield

**Status:** RATIFIED — Completed
**Date:** 2026-09-17
**Council:** Architecture Council, AdMe (6/6 ratified)
**Related:** COUNCIL-2026-001
**Tags:** council, automatic, live-governance, privacy, location

## Context
Digital advertisements frequently create negative user sentiment because they interrupt user focus without immediate tangible reward, and repeatedly displaying the same advertiser in short intervals creates severe ad fatigue and banner blindness. Users want immediate utility (real discounts, free items, or perks saved directly to their device wallet) rather than generic click-through redirects. Furthermore, users require active protection against repetitive ad bombardment during a browsing session without central surveillance tracking their session dwell.

## Decision
Implement an end-to-end Instant Value-Exchange Voucher Minting & Anti-Fatigue Attention Shield system: 1. Instant One-Tap Voucher Minting: Add an interactive 'Claim Deal to Wallet' component to FeedCard, NativeAdCard, and CarouselAdCard that extracts promotional offers, generates a unique redemption barcode/QR code, and persists the voucher directly into the user's Coupon Wallet and ledger with real-time conversion logging. 2. Client-Side Anti-Fatigue Attention Shield: Introduce on-device session fatigue tracking in sessionStorage and smart-feed ranking to enforce category anti-clustering (max 1-2 consecutive same-category items) and suppress over-served campaigns (frequency cap > 3 per session). 3. Attention Shield Transparency Badge: Add an interactive 'Attention Shield: Active' status indicator in the feed showing protected ads, rotation stats, and one-click session fatigue reset. 4. Advertiser Conversion Ledger: Track anonymous 'voucher_claim' events in Ad Studio analytics so merchants see high-intent local voucher adoptions alongside clicks and impressions.

## Amendments Adopted
1. All session fatigue tracking and frequency counters must reside exclusively in browser sessionStorage and clear automatically upon session termination.
2. Generated barcodes/QR codes for claimed vouchers must include an HMAC cryptographic signature to prevent counterfeiting at merchant checkout.
3. Ad Studio analytics must record 'voucher_claim' events completely anonymously, aggregating data to protect individual user privacy while providing merchants clear intent metrics.

## Implementation Mandate
Implement the Instant Value-Exchange Voucher Minting and Anti-Fatigue Attention Shield across FeedCard, NativeAdCard, and CarouselAdCard. Build a dedicated useAttentionShield custom hook leveraging sessionStorage for category anti-clustering and frequency capping (>3 per session). Create a secure Next.js API route for cryptographically signed voucher generation and RLS-protected coupon wallet persistence. Add the 'Attention Shield: Active' status indicator component with a one-click session fatigue reset. Update Ad Studio analytics to capture anonymous 'voucher_claim' conversion events.

## Council Deliberations
### 🏛️ The Architect (YES)
The architecture cleanly separates client-side state enforcement (sessionStorage for fatigue tracking) from persistent backend logic (voucher creation and ledger writes). Integrating 'Claim Deal to Wallet' directly into FeedCard, NativeAdCard, and CarouselAdCard requires a unified voucher minting hook. Next.js App Router API routes must handle the cryptographic signing of barcodes/QR codes to prevent tampering, while the client side efficiently manages reactive state for the Attention Shield badge.

### ⚙️ The Engineer (YES)
From a code complexity standpoint, implementing the client-side Anti-Fatigue Shield requires a robust custom React hook (e.g., useAttentionShield) that reads and writes to sessionStorage with graceful handling of quota limits or private browsing mode restrictions. TypeScript types must be strictly enforced for Voucher objects, campaign categories, and session metrics. Component props across FeedCard, NativeAdCard, and CarouselAdCard must be refactored cleanly to expose the 'Claim Deal to Wallet' callback without causing unnecessary re-renders.

### 🛡️ The Security Lead (YES)
The design fully respects zero-knowledge and privacy-first principles by keeping session dwell and fatigue counters strictly on the device via sessionStorage. For voucher claims, we must ensure Row-Level Security (RLS) restricts wallet entries exclusively to the authenticated user ID. Furthermore, generated barcodes/QR codes must incorporate HMAC signatures to prevent offline forgery or replay attacks at merchant point-of-sale terminals without deanonymizing the user.

### 🎯 The Product Owner (YES)
This directly targets the core user grievance of intrusive, repetitive ads with zero immediate reward. By offering instant utility ('Claim Deal to Wallet') and transparent protection against ad bombardment (Attention Shield Badge with one-click reset), we transform ads from a nuisance into a valuable service. This dramatically enhances user agency and engagement while preserving trust.

### 🧪 The QA Lead (YES)
Comprehensive test coverage is mandatory. We need unit tests for the sessionStorage wrapper, edge-case handling when sessionStorage is disabled or full, and ranking algorithm tests verifying category anti-clustering and frequency capping (>3 per session). Integration tests must validate the 'Claim Deal to Wallet' flow from card click to coupon wallet persistence and ledger logging.

### 💾 The Data Engineer (YES)
The database schema must support anonymous conversion logging for 'voucher_claim' events in Ad Studio without violating zero-retention compliance. Vouchers should link securely to user wallets and merchant campaigns via foreign keys, with indexes optimized for real-time conversion aggregate reporting. Session dwell metrics must never touch the server database, aligning fully with our ephemeral data ethos.
