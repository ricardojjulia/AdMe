# COUNCIL-2026-005: Online Ad Creative Editor, Direct Image Upload Validation, and Universal Offensive Content Reporting

**Status:** RATIFIED — Completed
**Date:** 2026-09-14
**Council:** Architecture Council, AdMe (6/6 ratified)
**Related:** COUNCIL-2026-001, COUNCIL-2026-004
**Tags:** council, governance, studio, image-validation, safety, moderation, user-agency

## Context
As AdMe transitions into active community usage, three critical operational and trust gaps have been identified:
1. **Ad Creative Editing Online**: Advertisers in Ad Studio (`/studio`) currently only have controls to edit daily budgets and toggle campaign status (pause/resume/archive). There is no inline editor to modify campaign creative copy, headlines, media images, or CTA buttons without permanently deleting the campaign and losing historical attention retention curves and analytics.
2. **Direct Image Upload & Client-Side Size Validation**: Campaign creation (`/studio/create`) relies solely on preset Unsplash photos or external URLs. There is no direct file upload, no client-side file size constraint, no MIME validation, and no canvas compression. Uploading or linking multi-megabyte uncompressed photos degrades consumer feed latency and mobile rendering performance.
3. **Universal Offensive Content Reporting**: While paid ads feature a basic report dropdown, organic posts and syndicated marketplace finds (`OrganicPostCard`) have no reporting mechanism beyond a local hide button. Furthermore, the existing moderation endpoint (`/api/moderation/report`) fails with 404 or foreign key exceptions when non-UUID syndicated items are reported.

## Decision
Ratify a 3-pillar safety, creative management, and quality control architecture:
1. **Direct File Upload with Strict 5MB Client Validation & Canvas Compression (`ImageUploader`)**:
   - Provide drag-and-drop and file selection supporting `image/jpeg`, `image/png`, and `image/webp`.
   - Strictly reject any file exceeding 5MB (`file.size > 5 * 1024 * 1024`) with an immediate client-side error toast/message.
   - Synchronously validate image dimensions (min 600x400) and execute client-side HTML5 Canvas downscaling to max 1200px width/height and WebP compression (0.85 quality) to ensure fast mobile rendering and eliminate bandwidth waste.
2. **Online Creative Ad Editor in Studio (`/studio`)**:
   - Introduce an `✏ Edit Creative` action in `/studio` for all active and paused campaigns.
   - Provide an accessible modal dialog (`EditCampaignModal`) permitting live updates to headline (60 chars), promotional copy (280 chars), creative image (via `ImageUploader`), CTA label, CTA URL, brand accent color, and target category.
   - Require automated pre-flight AI safety moderation (`/api/moderation/ad`) before persisting updates to the Supabase `ads` table.
3. **Universal Offensive Content Reporting Modal (`ReportModal`)**:
   - Deploy a standardized, accessible reporting modal across `NativeAdCard`, `FeedCard`, `CarouselAdCard`, and `OrganicPostCard`.
   - Provide clear, actionable safety categories: `Offensive or Inappropriate`, `Scam or Fraudulent`, `Misleading / Fake Claim`, `Spam`, `Dangerous or Illegal`.
   - Immediately apply optimistic feed removal, update client-side suppression lists in `UserContext` and `localStorage`, and arbitrate the report via `/api/moderation/report` gracefully regardless of whether the item is a Supabase ad or syndicated marketplace discovery.

## Amendments Adopted
1. **Strict 5MB Client-Side Boundary**: File validation must occur in memory before any network request or upload buffer initialization. Files $>5\text{MB}$ must be rejected instantly with user-friendly guidance.
2. **AI Safety Gate Invariant on Edits**: Updating an active ad's copy or headline must re-trigger the automated Gemini safety moderation pipeline (`/api/moderation/ad`). Campaigns that fail moderation cannot be saved and must alert the advertiser.
3. **Graceful Syndicated Content Arbitration**: The moderation reporting endpoint must decouple from strict foreign-key database dependencies. Syndicated or non-UUID posts must be arbitrated on headline and body content, returning instant arbitration decisions without database errors.
4. **Optimistic Consumer Shielding**: When a user reports any card (ad or marketplace find), the UI must instantly remove the card from the active viewport, persist the dismissal locally, and provide immediate reassurance feedback.

## Implementation Mandate
1. Create `src/components/ImageUploader.tsx` and `src/components/ImageUploader.module.css` with 5MB validation, dimension verification, and canvas compression.
2. Integrate `ImageUploader` into `src/app/studio/create/page.tsx` alongside preset selections.
3. Build the Campaign Creative Editor modal in `src/app/studio/page.tsx` with full creative editing and pre-flight AI moderation.
4. Create `src/components/ReportModal.tsx` and `src/components/ReportModal.module.css` providing the standardized reporting experience.
5. Integrate `ReportModal` into `src/components/OrganicPostCard.tsx`, `src/components/NativeAdCard.tsx`, and `src/components/FeedCard.tsx`.
6. Update `src/app/api/moderation/report/route.ts` and `src/lib/UserContext.tsx` to support reporting both platform ads and syndicated marketplace items.
7. Verify all unit tests pass with `npm run test` and TypeScript check passes with `npm run typecheck`.

## Council Deliberations

### 🏛️ The Architect (YES)
The architectural separation of concerns is clean and addresses genuine product deficiencies. Offloading image resizing and format normalization to client-side HTML5 Canvas before payload generation saves cloud egress and keeps the database responsive. Integrating the Ad Creative Editor directly into `/studio` preserves existing analytics identifiers while ensuring zero downtime for live campaigns. The decoupling of `/api/moderation/report` from direct table joins allows the same moderation pipeline to service both first-party paid ads and third-party syndicated items seamlessly.

### ⚙️ The Engineer (YES)
The implementation is straightforward and highly maintainable. The `ImageUploader` component encapsulates file picking, MIME filtering, size validation, and Canvas rendering into a single reusable React hook/component. For the Ad Editor, we reuse the existing `ads` update mutation pattern and invoke the existing `/api/moderation/ad` endpoint prior to committing changes. For reporting, replacing ad-hoc dropdowns with a centralized `ReportModal` reduces duplicated JSX across `NativeAdCard`, `FeedCard`, and `OrganicPostCard`.

### 🛡️ The Security Lead (YES)
Enforcing client-side 5MB limits and MIME type whitelisting (`image/jpeg`, `image/png`, `image/webp`) prevents memory-exhaustion vectors and malicious file upload exploits. Re-running AI safety checks on ad edits prevents a common attack vector where bad actors publish benign ads to pass initial review, then edit them into scam or offensive content later. Decoupling report submissions prevents SQL/Postgres foreign key exception leaks to the client.

### 🎯 The Product Owner (YES)
This directly resolves top user experience complaints. Advertisers can finally fix typos, update seasonal imagery, and adjust call-to-actions without destroying their campaign metrics. On the consumer side, having a clear 'Report Offensive Post' button on marketplace items and ads alike gives users agency and safety. The instant removal ensures that offensive material never remains visible once reported.

### 🧪 The QA Lead (YES)
All requirements are testable with automated assertions. We will write unit tests verifying that files $>5\text{MB}$ are rejected, valid images produce optimized output, the Ad Creative Editor updates state and triggers moderation, and reporting an organic post invokes the moderation API and removes the card from view.

### 💾 The Data Engineer (YES)
The database schema for `ads` already has all required columns (`headline`, `content_text`, `media_url`, `cta_label`, `cta_url`, `primary_color`, `updated_at`). For `ad_reports`, we will ensure that reports for non-database items do not violate foreign keys by handling them gracefully at the service layer.
